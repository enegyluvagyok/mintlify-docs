Az architektúraterv az Analyse platform teljes rendszertervezési képét adja meg — a technológiai választásoktól a skálázási szempontokon át a biztonsági elvekig.

## Áttekintés

Az Analyse egy webalapú, Laravel \+ Livewire alapú QA-menedzsment platform, szerver-oldali renderelt UI-jal és MySQL adatbázissal. A tervezés során az alábbi szempontok kaptak prioritást:

- **Megbízhatóság** — Redundáns infrastruktúra, automatikus feladatátvétel
- **Biztonság** — Szerepkör-alapú hozzáférés, titkosítás, auditnapló
- **Karbantarthatóság** — Moduláris kódbázis, API-first szemlélet
- **Skálázhatóság** — Vízszintes skálázás támogatása a stateless alkalmazásrétegben

## Kulcsfontosságú tervezési döntések

### Livewire-alapú reaktív UI

A frontend nem különálló SPA, hanem Laravel Blade template-eken alapuló, Livewire komponensekkel megvalósított reaktív felület. Az állapotkezelés szerver oldalon történik — nincs szükség külön REST API-ra a UI és a backend között. Alpine.js biztosítja a kliens-oldali kisebb interakciókat (dropdown, modal, stb.).

### Filament 4 admin panel

A rendszer adminisztrációs felülete Filament 4 alapú (`/admin`). A felhasználókezelés, projektek, szerepkörök és egyéb beállítások itt érhetők el. A Filament activity log plugin (`pxlrbt/filament-activity-log`) naplózza a kritikus adminisztrációs műveleteket.

### Laravel Octane (Swoole)

Az alkalmazás Laravel Octane 2 \+ Swoole alapon fut, amely persistent worker folyamatokat tart fenn, jelentősen csökkentve a request-per-second latenciát a hagyományos PHP-FPM megközelítéshez képest.

### Laravel Reverb (WebSocket)

A valós idejű értesítések Laravel Reverb 1.6 önhosztolt WebSocket szerveren keresztül működnek. A Reverb egy önálló, hosszan futó PHP folyamat (`php artisan reverb:start`), amelyet Supervisor felügyel.

**Kommunikációs folyamat:**

1. A Laravel alkalmazás `broadcast(new SomeEvent())` hívást tesz
2. Laravel → Redis pub/sub csatornán publikálja az eseményt
3. Reverb feliratkozik a Redis csatornára → WebSocket push a klienseknek
4. A böngészőben futó **Laravel Echo** (pusher-js driver) megkapja az eseményt → UI frissítés Livewire-en belül

**Kapcsolódó .env változók:**

| Változó | Példa | Leírás |
| --- | --- | --- |
| `BROADCAST_CONNECTION` | `reverb` | Broadcast driver |
| `REVERB_APP_ID` | `my-app-id` | Reverb alkalmazás azonosító |
| `REVERB_APP_KEY` | `my-app-key` | Reverb kulcs (Echo is ezt használja) |
| `REVERB_APP_SECRET` | `my-app-secret` | Reverb titkos kulcs |
| `REVERB_HOST` | `127.0.0.1` | Reverb belső hosztneve (Supervisorban is `127.0.0.1`) |
| `REVERB_PORT` | `8080` | Reverb szerver portja |
| `REVERB_SCHEME` | `http` | Reverb belső kommunikációja HTTP — SSL terminálás Nginxnél történik |
| `VITE_REVERB_APP_KEY` | `${REVERB_APP_KEY}` | Echo kliens kulcs (Vite-on át) |
| `VITE_REVERB_HOST` | `${REVERB_HOST}` | Echo kliens hoszt |
| `VITE_REVERB_PORT` | `${REVERB_PORT}` | Echo kliens port |
| `VITE_REVERB_SCHEME` | `${REVERB_SCHEME}` | Echo kliens scheme |

**Nginx WebSocket proxy konfiguráció** (a fő `server` blokkba):

```nginx
location /app {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 60s;
}
```

**Supervisor konfiguráció** (`/etc/supervisor/conf.d/analyse-reverb.conf`):

```ini
[program:analyse-reverb]
command=php /opt/analyse/artisan reverb:start --host=127.0.0.1 --port=8080
autostart=true
autorestart=true
user=www-data
redirect_stderr=true
stdout_logfile=/opt/analyse/storage/logs/reverb.log
```

### MVC \+ Service réteg

Az üzleti logika Laravel Controller → Service → Repository/Model rétegeken keresztül van szervezve. Az Eloquent ORM kezeli a MySQL adatbázis-interakciókat. A komplex, időigényes műveletek (PDF-export, tömeges e-mail) Laravel Queue job-ként futnak Supervisor felügyelet alatt.

### Adatbázis-izoláció

Az adatbázis-kiszolgáló nem érhető el közvetlenül az internetről — kizárólag az alkalmazásréteg kommunikálhat vele a belső hálózaton keresztül.

### Aszinkron műveletek

Az időigényes folyamatok (pl. PDF-exportálás, tömeges e-mail-értesítések) aszinkron módon, háttérfeladatként futnak, hogy ne blokkolják a felhasználói kéréseket.

## Biztonsági architektúra

- **Hitelesítés:** Laravel session-alapú auth \+ Laravel Sanctum, CSRF-védelem Livewire-en beépítve
- **Hozzáférés-vezérlés:** Laravel Gate \+ Policy réteg (RBAC), minden route és Livewire action védett
- **Adattitkosítás:** TLS 1.2\+ az összes kommunikációhoz; érzékeny mezők Laravel `encrypt()` segítségével tárolva
- **Input validáció:** Laravel Form Request osztályok és Livewire `$rules` validáció, kizárólag szerver oldalon
- **CSRF-védelem:** Laravel beépített CSRF token minden form-on és Livewire kérésben
- **Rate limiting:** Laravel `throttle` middleware az érzékeny route-okon

## Skálázási szempontok

| Forgatókönyv | Megközelítés |
| --- | --- |
| Több egyidejű felhasználó | Octane `--workers` növelése, Nginx upstream pool (több Octane node), Supervisor queue worker pool |
| Nagy adatmennyiség | MySQL master–replica replikáció; Eloquent `read`/`write` connection szétválasztás |
| Magas exportigény | Laravel Queue \+ Redis driver, Job chain PDF/Excel generáláshoz |
| Globális elérhetőség | CDN a `public/build/` Vite-assetekhez, multi-region telepítés |
| Livewire skálázás | Redis session driver, Laravel Octane (Swoole) persistent worker pool |
| WebSocket skálázás | Laravel Reverb horizontálisan skálázható; Redis publish/subscribe bus |
| Adatbázis karbantartás | MySQL 8 online DDL — minimális leállás `php artisan migrate` futtatásakor |
